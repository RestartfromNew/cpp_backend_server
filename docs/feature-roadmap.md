- 当前已有设备登录 ticket、Refresh Token 绑定设备和撤销联动；信封以目标设备保存，packet 限 64 KiB。

## 已确定的路线

|---|---|---|---|
| P0 | 固化文字/多设备基线 | 1–2 | 去重、ACK、重启恢复、撤销有记录 |
| P1 | FileStorage、磁盘执行器与普通头像 HTTP | 3–5 | 单请求校验保存、原子替换、active/revoked、维护清理 |

## P1：头像

普通 HTTP /upload_avatar 接受限小原始图片，校验像素/格式、缩放去元数据、重编码 JPEG，通过共用磁盘池存入 Linux 私有目录。成功后同一短事务插入 avatars、切换 user_avatars、撤销旧头像并记录 revoked_at，再返回结果。

头像不 E2EE、不进入 file_uploads、不申请上传许可、不走附件 Reactor、不做用户累计空间预留。保留输入/输出上限、频率、全局并发和临时容量控制。维护线程分批挑选超过宽限期且未引用的 revoked 头像，磁盘池执行删除，失败重试。

## P2：附件上传

file.upload.request 经当前认证的 WebSocket 申请，request_id 持久化为上传创建幂等键，业务池保存 attachment/file_uploads 并回投 Worker。iOS 拿上传地址与凭据，独立 HTTP 传已加密文件；网络 Reactor 分块读，磁盘池顺序写，队列满背压。

文件写入/校验/持久化后记录 ready，再尽力提示 file.upload.ready。WebSocket 正常断开不取消 HTTP 上传，重连用 status 查询。renew/cancel 与接收认领串行化，凭据不写日志。第一版无字节断点续传。

## P3：消息、文件和 iOS

文件密文保存磁盘；packet 只存加密的附件描述、文件密钥、参数和时间。外层 attachment_ids 与 message_envelopes 同事务关联 envelope_attachments；不因参数重试额外授权。

在线推送/离线补拉均走现有信封链路，Bob 解密后另经 HTTP 下载，再本地认证解密。ACK 表示信封已保存，不等待图片下载。时间展示用逻辑消息 sent_at，不以附件上传时间排序；设备对 seq 不当作整个聊天序号。

缩略图也需客户端加密，不让服务端处理未知明文。先限制小图片/文件；上限由配置和真机内存测试确定，不同时引入群聊、视频、分块随机访问和历史迁移。

## 后置范围

- file_storage_quotas：保留独立 SQL 草案，本阶段可不建；单文件、活动任务和全局磁盘限制仍必须执行。envelope_attachments 是现有设备授权方案的一部分，不能在无替代授权时跳过。
- APNs：考虑会员费用暂缓，后续基于信封提交与持久化通知任务接入。第一版通用提醒、点击后同步，不传聊天明文和文件密钥。原排期的 4–7 天仅为早期粗估。
- 对象存储直传和多机：先封装 FileStorage，用 Linux 磁盘验证；未来存储实现可以替换，不提前承诺仅改配置即可多机运行。
- 大文件断点续传：需要上传协议、加密格式、状态检查点、期限和鉴权联合设计。
